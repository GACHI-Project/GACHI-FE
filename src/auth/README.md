# HTTP와 인증 세션

## 책임과 호출 방향

- `src/config/api.ts`: `EXPO_PUBLIC_API_BASE_URL`과 공통 요청 제한 시간. 환경변수가 없으면 기존 서버 주소를 사용한다.
- `src/api/client.ts`: Axios 인스턴스와 인터셉터. 요청에 세션 버전을 고정하고, 인증 요청의 401에 한 번만 토큰 갱신과 재전송을 수행한다.
- `src/api/errors.ts`: 서버 오류 코드·메시지·HTTP 상태를 보존하는 `ApiError`와 공통 변환 함수. 도메인별 오류 클래스는 이를 상속한다.
- `src/api/auth.ts`: 로그인·가입·소셜 계정 연결 등 인증 API. 토큰 저장이나 앱 화면 이동을 담당하지 않는다.
- `src/auth/session.ts`: SecureStore 접근, 직렬 토큰 저장, 세션별 단일 갱신 요청, 자격 증명 삭제와 삭제 실패 결과.
- `src/auth/logout.ts`: 서버 로그아웃 요청 후 현재 세션의 로컬 정리를 수행하는 흐름.
- `src/auth/sessionEffects.ts`: 회원가입·소셜 인증 스토어 초기화, Google SDK 로그아웃, 로그인 화면 이동.
- `src/auth/useSessionEffects.ts`: 앱에서 정리 콜백의 설치·해제를 관리하고 네비게이터 준비 이후 화면 이동.
- `src/utils/authSession.ts`: 세션 버전·인증 가능 여부와 변경 구독. Query 캐시는 이 구독을 통해 초기화된다.

도메인 API는 `api/client`와 `auth/session`을 직접 사용한다. HTTP와 세션 모듈은
화면·스토어·Google SDK를 가져오지 않는다. `app/_layout.tsx`의 `useSessionEffects`가
정리 콜백을 설치하고 언마운트 시 해제한다. 설치 함수는 중복 호출 시 같은 해제 함수를 반환한다.
폰트·언어 초기화와 네비게이터의 ready 이벤트를 모두 기다린 뒤 로그인 화면으로 이동한다.
대기 중 새 로그인이 완료되거나 세션이 바뀌면 이전 화면 이동은 취소한다.

## 세션 정리 순서

`clearSession()`은 중복·재진입 호출에 같은 Promise를 반환한다. 정리 작업을 먼저 예약하고
세션 버전을 변경해 이전 요청·갱신 결과를 무효화하며, 진행 중인 갱신은 취소한다.

1. `invalidated`: 앱의 회원가입·소셜 인증 스토어를 각각 독립적으로 초기화한다.
2. 진행 중인 토큰 저장을 기다린 뒤 `clearing-tokens`에서 Google SDK 로그아웃을 시작한다.
   SDK 응답 지연·실패는 로컬 자격 증명 삭제를 막지 않는다.
3. 두 토큰을 삭제하고 실패한 키만 한 번 더 삭제한다. 영구 실패 키는 `SessionCleanupResult`로 반환한다.
4. 자동 로그인 설정을 삭제하고 `cleared`에서 로그인 화면 이동을 요청한다.

앱 콜백이 실패해도 나머지 콜백과 자격 증명 삭제는 계속한다. 콜백을 설치하지 않은 환경에서도
토큰 삭제와 세션·캐시 무효화는 작동한다. 삭제에 실패한 토큰이 남아도 해당 세션에서는
인증 요청을 보내지 못하며, 새 로그인에서 토큰 저장이 완료돼야 다시 인증 상태가 된다.
토큰 쌍 저장에 실패하면 진행 중인 쓰기가 끝난 후 세션을 정리해 새 액세스 토큰과
이전 갱신 토큰이 섞인 상태를 유지하지 않는다. 이 경우 로그인·소셜 연결을 다시 시도해야 한다.

## 오류와 취소

모든 도메인은 `toApiError(error, DomainApiError)`를 사용한다. 서버 응답의 코드가 없으면
`HTTP403`처럼 HTTP 상태에서 코드를 만들며, 메시지가 없으면 공통 기본 메시지를 사용한다.
`UserApiError`, `AuthApiError` 등의 `instanceof` 판별과 서버 코드 비교는 유지한다.
정상 HTTP 응답에 포함된 업무 실패 처리는 각 도메인에 남겨 둔다.

Axios 취소 오류는 원본 그대로 전달한다. 응답이 없는 네트워크·시간 초과 오류도 원본과
오류 코드를 유지한다. 토큰 갱신은 인터셉터가 없는 전송 경로를 사용해 재귀 갱신을 막고,
일반 API와 같은 환경별 서버 주소·제한 시간을 사용한다.
늦게 도착한 이전 토큰의 401은 이미 저장된 최신 토큰을 재사용하고 추가 갱신을 시작하지 않는다.
최신 토큰 확인은 별도로 수행하며 실제 재발급 요청만 공유해 동시 요청의 필요한 갱신을 막지 않는다.
갱신 대기 중 한 요청이 취소되면 그 요청은 즉시 종료하되 다른 요청의 공유 갱신은 유지한다.
로그아웃된 세션은 삭제 실패로 갱신 토큰이 남아 있어도 직접 갱신할 수 없다.
자동 로그인 설정 읽기·쓰기도 저장소 응답 이후 세션 버전을 확인한다.

## 검증

`npm run test:auth`는 실제 Axios 인터셉터와 격리된 SecureStore·전송 구현을 연결한다.
동시 401, 토큰 저장·삭제 경합, 이전 세션 응답, 갱신 중 로그아웃, 정리 콜백 재진입,
환경별 서버 주소, 도메인 오류 타입·HTTP 상태 및 취소·시간 초과 정보 보존을 검증한다.
