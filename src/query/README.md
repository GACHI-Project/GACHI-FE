# 서버 상태 관리

서버 데이터는 TanStack Query 캐시에 보관한다. 폼 입력값은 React Hook Form,
모달·선택 항목·애니메이션·인증 타이머는 화면 또는 전용 훅에서 관리한다.
Zustand에는 회원가입 초안과 소셜 인증 진행 상태만 보관한다.

## 구성

- `client.ts`: QueryClient, 세션별 캐시 초기화, 도메인 무효화
- `QueryProvider.tsx`: React Native AppState 및 NetInfo 연동
- `hooks.ts`: 화면 query, mutation, 입력 디바운스
- `options.ts`: 일반 query 및 문서 페이지네이션 옵션
- `resources.ts`: 여러 화면이 공유하는 자녀·프로필·급식·시간표 조회
- `checklists.ts`: 화면 간 체크리스트 변경 동기화와 항목별 복구
- `notifications.ts`: 알림 페이지네이션 및 읽음 상태 동기화
- `operations.ts`: 로그인 완료·푸시 토큰 등 React 밖에서 실행하는 요청
- `state.ts`: 최초 조회 오류와 일시적인 재조회 오류 구분
- `profile.ts`: 저장이 확인된 알림 설정의 프로필 캐시 반영
- `calendar.ts`: 날짜 수정·일정 등록의 순서 보장과 캐시 갱신
- `schools.ts`: 학교 코드·교육청 코드로 검증한 학교 상세 조회 옵션

## 키와 조회 정책

키 형식은 `['session', sessionVersion, language, domain, ...conditions]`이다.
자녀, 검색어, 날짜, 페이지 구분처럼 결과에 영향을 주는 조건을 빠짐없이 넣는다.
무한 목록의 개별 페이지 번호는 `pageParam`으로 전달한다.

기본 staleTime은 30초, gcTime은 5분이다. 급식·시간표·학교 검색은 5분간
재사용하고, 알림·분석 상태·인증 중복 검사는 즉시 최신 상태를 확인한다.
화면 재진입 시 해당 키만 무효화하며, 최초 조회와 키 변경 시에는 추가 조회를
중복 실행하지 않는다. 앱 활성화와 네트워크 재연결은 Query의 수명주기에 연동한다.
언어 설정 변경은 서버 수정 후 현재 세션의 조회를 취소하고 캐시를 제거한 다음
화면 언어를 바꾼다. 서버가 선택한 언어로 만든 응답을 이전 언어 키에 보관하지 않는다.

조회 함수는 전달받은 AbortSignal을 `src/api` 함수의 마지막 인자로 전달한다.
API 계층은 이를 Axios config.signal까지 전달한다. `state.ts`의 `isTransientQueryError`를
자동 재시도와 수동 재시도 버튼에서 공유한다. 인증 오류, 일반 4xx, 취소는 자동 재시도하지
않으며 네트워크 오류·408·429·5xx 같은 일시적인 조회 실패만 최대 2회 재시도한다.

## 수정과 인증 세션

컴포넌트의 서버 수정은 `useApiMutation`을 사용하고, 관련 도메인을 지정해
성공·실패 후 서버 상태를 재확인한다. 동일 훅의 같은 인자 요청은 진행 중에 공유한다.
수정 요청은 자동 재시도하거나 오프라인 상태에서 재연결까지 대기시키지 않는다.
컴포넌트 밖의 작업은 `executeSessionMutation`을 사용한다.
캐시 재조회까지 끝난 시점에도 세션을 확인해, 재조회 중 계정이 바뀌면 이전 작업을
취소로 처리한다. 소셜 연결은 교체된 토큰을 저장한 뒤 프로필 캐시를 갱신한다.

토큰 저장과 동시 401 재발급은 `src/auth/session.ts`가 담당하며,
`src/api/client.ts`의 인터셉터가 요청 세션을 확인하고 재전송한다.
앱 스토어 초기화와 화면 이동은 HTTP 모듈에서 분리한다. 자세한 순서는
[HTTP와 인증 세션](../auth/README.md)을 참고한다.
로그아웃·탈퇴·인증 실패로 세션을 무효화하면 query를 취소하고 캐시를 비운다.
조회·수정 작업은 시작한 세션을 확인하므로 이전 계정의 결과나 콜백이 새 계정의
캐시를 수정할 수 없다. Query 캐시는 메모리에만 유지하고 인증 토큰은 SecureStore에 보관한다.

체크리스트 변경은 항목별 잠금을 공유한다. 실패한 항목만 복구하며 다른 항목의
성공 결과를 되돌리지 않는다. 변경 전 시작된 조회에는 진행 중·확정 변경을 적용한다.
같은 수정은 진행 중 요청을 공유하고, 토글 중 삭제는 토글이 끝난 뒤 실행한다.
동시 삭제의 복구 위치는 작업들이 시작되기 전 순서를 기준으로 정한다.
새 수정은 대상 항목에만 적용하고, 처리가 끝나면 관련 조회를 무효화해 응답 유실도
서버 상태와 맞춘다. 수정 중 처음 조회된 화면도 실패 시 복구 대상에 포함한다.
알림 개수는 서버의 unread-count 응답을 기준으로 하며, 읽음 응답의 readCount는
잔여 개수가 아니라 실제 변경된 개수로 사용한다. 응답 유실 시 서버 목록을 재조회한다.
푸시 갱신은 진행 중인 총계 조회를 취소해 푸시 이후의 새 총계를 요청한다.

## 화면 상태

렌더링용 검증 결과는 state와 useWatch에서 계산하고, 요청 제어용 ref는 이벤트와
비동기 작업에서만 읽는다. 이메일 발송·확인은 mutation이지만 주소·코드 변경,
재발송, 화면 이탈에 따른 결과 무효화와 인증 만료는 전용 훅의 규칙으로 유지한다.
알림 설정 초안은 저장 중에만 유지한다. 완료 후에는 프로필 캐시를 표시하고,
저장 중 충돌하는 입력은 막으며 실패하면 확인된 서버 값으로 복구한다.
저장이 성공한 값은 재조회 전에 캐시에 반영하므로, 후속 조회 실패로 이전 설정을
다시 표시하지 않는다. 조회 실패 시 기존 데이터가 있으면 일시적 오류를 따로 안내하고,
첫 조회 실패나 접근 거부에는 오류와 재시도를 제공한다.
오늘 할 일은 날짜를 키에 포함해 자정·백그라운드 복귀 시 날짜와 목록을 함께 바꾼다.

자녀 수정 화면은 응답에 주소가 있으면 사용하고, 없으면 학교명으로 검색한 최대 20개
결과에서 학교 코드와 교육청 코드가 모두 일치하는 주소만 표시한다. 학교 식별자와
학교명을 포함한 Query 키로 요청과 5분 캐시를 공유한다. 주소는 편집 초안에 쓰지 않고
표시할 때만 보완하므로 늦은 응답·조회 실패가 이름·학년·반·학교 선택과 저장을 막지 않는다.
재진입 시 캐시를 재사용하고, 앱 재실행 후에는 자녀 응답의 식별자로 다시 조회한다.
마이페이지에서 자녀 목록을 받으면 학교 주소와 반 목록을 병렬로 미리 조회한다.
시트는 진행 중인 요청과 캐시를 공유하고, 반 목록을 기다릴 때도 기존 반을 바로 표시한다.
학교명 조회 조건과 캐시 반영은 `canFetchSchoolDetails`·`cacheSchoolDetails`로 통일하고,
반 목록은 `schoolClassesResource`·`schoolClassesOptions`를 화면 조회와 사전 조회에서 공유한다.
자녀 수정 시트는 저장·삭제가 끝날 때까지 입력·버튼·닫기를 막는다. 현재 시트에서 시작한
요청만 성공 시 시트를 닫거나 실패를 안내하며, 실패하면 편집값을 유지해 재시도한다.
시트 재진입·편집 대상 변경·언마운트·계정 변경 후에는 이전 요청의 UI 처리를 무시한다.

현재 백엔드의 [자녀 응답](https://github.com/GACHI-Project/GACHI-BE/blob/develop/src/main/java/com/gachi/be/domain/child/dto/response/ChildResponse.java)에는
주소가 없고, [학교 검색](https://github.com/GACHI-Project/GACHI-BE/blob/develop/src/main/java/com/gachi/be/domain/school/api/controller/SchoolController.java)은
학교명 검색과 최대 20개 결과만 지원한다. 대상이 검색 결과에 없으면 기존 학교명과
편집값을 유지한다. 모든 동명 학교의 주소를 보장하려면 백엔드에 코드 기반 조회 또는
페이지네이션이 필요하다.

문서 분석은 업로드 요청 완료와 실제 분석 완료를 구분한다. 상태 조회가 COMPLETED가
되면 문서 목록·요약·번역 등 결과 캐시를 다시 무효화한다.

스캔 로딩 화면은 `useNewsletterProcessing`의 처리 단계(`starting`, `processing`,
`paused`, `completed`, `failed`, `error`, `idle`)를 표시한다. 서버 상태는 Query가,
시작 요청·사용자 명령·오류는 훅이 관리하며 완료 여부와 일시정지를 별도 state로 복제하지 않는다.
시작 응답의 상태는 조회 데이터가 없을 때만 화면에 임시 표시하며 공유 상태 캐시에 쓰지 않는다.
임시 상태로는 쓰기 명령을 허용하지 않으며, 실제 조회 결과의 재시도·건너뛰기 권한을 따른다.
진행 중에는 2초 간격으로 상태를 조회하고 완료·실패·일시정지·조회 오류에서는 폴링을 멈춘다.
네트워크·서버 오류의 자동 재시도는 공통 Query 정책에 따라 최대 2회로 제한하며,
권한·입력 오류는 자동 재시도하지 않는다. 상태 조회 실패의 수동 재시도는 GET만 실행한다.
재개·분석 재시도·페이지 건너뛰기는 동기 잠금으로 직렬화하고, 성공 후 기존 상태 조회를
취소한 뒤 새 상태를 조회한다. 후속 GET 실패로 성공한 쓰기를 자동 반복하지 않는다.
쓰기 실패 알림의 재시도는 실패한 명령을 유지하며, 건너뛰기는 같은 페이지일 때만 다시 실행한다.
명령 전송 직전에 공유 캐시와 명령 판별 스냅샷을 비교하고, 다르면 화면 갱신까지 전송을 막는다.
쓰기 실패마다 고정 식별자로 알림 중복을 제거하므로 진행률 갱신은 같은 오류를 다시 알리지 않는다.
새 쓰기 실패와 새 상태 조회 실패는 각각 별도 알림을 표시한다.
문서 입력·세션 변경은 layout effect에서 이전 작업을 무효화하고 화면 이탈도 포커스
정리로 처리한다. 이미 전송한 쓰기가 서버에서 끝나더라도 이전 콜백은 새 화면의 상태·알림을
바꾸지 않는다. 같은 시작 요청은 effect 재실행·포커스 복귀 시 재사용한다.
사진 목록은 값이 같으면 같은 입력으로 취급해 배열 참조 변경으로 초기화하지 않는다.
최신 상태 조회 오류는 완료 캐시와 이전 명령 오류보다 우선한다. 재시도·건너뛰기 버튼과
실제 요청은 같은 명령 판별 함수를 사용하며, 오류 재시도 중에는 완료 화면으로 전환하지 않는다.
`useNewsletterProcessingAnimation`은 처리 단계만 구독하고 일시정지·실패·이탈 시 반복
애니메이션을 정리하며 문서 변경 시 완료 표시를 초기화한다.

일정 저장 시트는 열 때
조회한 일정과 편집값을 하나의 초안으로 유지하고, 다시 열면 새 조회로 초안을 만든다.
날짜 PATCH와 등록 POST 사이에는 재조회를 기다리지 않는다. 날짜 수정만 성공한
경우에도 확인된 날짜를 캐시에 반영하며, 등록 작업 종료 후 관련 조회를 갱신한다.
유효한 초안은 일시적인 조회 실패에도 편집·등록할 수 있고, 만료된 미리보기는 차단한다.

## 검증

`npm test`는 실제 QueryClient·QueryObserver·InfiniteQueryObserver의 캐시와
요청 수명주기, 인증 세션, 회원가입 검증, 다국어 레이아웃 테스트를 실행한다.
테스트별 QueryClient를 격리하고 재시도와 캐시 GC 타이머를 제어한다.
스캔 처리 테스트는 실제 `useApiMutation`·`MutationObserver`를 연결해 캐시 무효화 대기 중
문서 변경·포커스 복귀·세션 종료를 검증하며, 고정 지연 대신 요청과 상태 조건을 기다린다.
`npm run test:query`로 공통 캐시와 Native 이벤트 연동을 따로 확인할 수 있다.

NetInfo는 Expo 55 권장 버전인 11.5.2로 고정한다. 네이티브 의존성이므로 기존 개발
클라이언트 사용자는 Android/iOS 앱을
다시 빌드해야 한다. 네트워크 전환·백그라운드 복귀·계정 전환은 실기기에서도 확인한다.
